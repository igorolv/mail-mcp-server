## 1. Протоколы доступа к Exchange on-premise

| Протокол | Что это | Плюсы | Минусы / риски | Статус |
|---|---|---|---|---|
| **EWS** (Exchange Web Services, SOAP) | `/EWS/Exchange.asmx` | Полный доступ к почте, папкам, вложениям, поиску; `SyncFolderItems` для инкрементальной синхронизации; MIME-содержимое письма | Устаревает (в Exchange Online выводится из эксплуатации), но для on-prem — основной путь; SOAP многословен | ✅ работает у нас: Exchange 2013, вход из кода по NTLM (логин `user`), см. plan.md 3.1–3.2 |
| **Exchange ActiveSync** (EAS) | То, что использует iPhone | Точно работает у нас | Протокол для мобильных устройств, сложный (WBXML), сервер может требовать политики устройства; для интеграции не предназначен | ⬜ |
| **IMAP / SMTP** | Стандартные протоколы | Много библиотек (Jakarta/Angus Mail) | В Exchange on-prem часто выключены; проверить | ⬜ |
| **Microsoft Graph** | REST API Microsoft 365 | Современный | Для чистого on-prem недоступен (только Exchange Online / гибрид) | ⬜ |
| **OWA** (веб-интерфейс) | `/owa` | Точно работает у нас | Внутренний API, не для интеграции; скрапинг — хрупко | ⬜ |
| **MAPI over HTTP** | Протокол Outlook | Полный | Закрытый, сложный | ⬜ |

Что проверить на нашем сервере — см. [plan.md, раздел 9](plan.md#9-ближайшие-шаги).

### 1.1. Личные ящики: Gmail и Mail.ru

Всё в таблице — по памяти, требует проверки на актуальных условиях провайдеров.

| Вариант | Что это | Плюсы | Минусы / риски | Статус |
|---|---|---|---|---|
| **Gmail по IMAP** (`imap.gmail.com:993`) | Стандартный IMAP | Та же реализация, что для Mail.ru; расширения `X-GM-MSGID`, `X-GM-THRID`, `X-GM-LABELS` | Вход — пароль приложения (нужна двухэтапная проверка) или OAuth2 (`XOAUTH2`); Google ужесточает доступ «простым паролем»; метки вместо папок → дубли в «Вся почта» | ⬜ |
| Gmail API (REST) | Собственный API Google | Метки, треды, история изменений (`history`) — удобная инкрементальная синхронизация | Нужен свой OAuth-клиент в Google Cloud; отдельная реализация источника | ⬜ |
| **Mail.ru по IMAP** (`imap.mail.ru:993`) | Стандартный IMAP | Та же реализация, что для Gmail | Нужен «пароль для внешнего приложения»; поддержку `CONDSTORE`/`QRESYNC` проверить | ⬜ |

## 7. jdbc-mcp-server — список соединений

Источник: `C:\git\jdbc-mcp-server` (`docs/connections.md`, `docs/read-only.md`, пакет
`connection/`: `ConnectionsLoader`, `ConnectionsFile`, `ConnectionDefinition`,
`ConnectionRegistry`, `EnvironmentPlaceholders`; `tools/ConnectionTools`, `ToolConnections`).

| Элемент | Как там | Для почты | Статус |
|---|---|---|---|
| Файл соединений | `connections.json` в каталоге данных; `JDBC_MCP_CONNECTIONS_FILE`, `JDBC_MCP_DATA_DIR`; читается при старте | Берём: `%USERPROFILE%\.mail-mcp-server\connections.json` | ✅ |
| Имя соединения | Ключ записи, `[A-Za-z0-9._-]+(@…)?`, ≤ 64; = каталог данных и часть URI ресурсов | Берём как есть | ✅ |
| Выбор соединения | Нет соединения по умолчанию; `connection` — первый аргумент каждого инструмента | Берём для чтения; для поиска, возможно, «все ящики» (plan.md 5.7) | ✅ |
| `listConnections` | Только конфигурация, `configError`, без подключения | Берём | ✅ |
| Изоляция | Ленивое создание, блокировка на соединение, ошибка не кэшируется | Берём | ✅ |
| Секреты | В файле, `${VAR}` в любой строке, незаданная переменная — ошибка старта; права через `icacls` | Берём; плюс хранение OAuth-токенов Gmail | ✅ |
| Неизвестные ключи | Молча игнорируются | Лучше предупреждать в логе — опечатка в `folders` незаметна | ✅ |
| Логи | MDC с именем соединения | Берём | ✅ |
